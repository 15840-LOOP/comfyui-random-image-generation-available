## 二、三个需求的实现结果

### 需求 1：组合禁用

**目标**：从已生成的图片上，选择若干维度禁用该搭配，避免全随机时出现不美观的组合。

**规则语义**（经用户确认）：
- 只禁"这一对搭配"，不拉黑单个条目
- 勾选多个维度时，**全部同时命中**才跳过（AND 语义）
- 存 `<section>:...` 的 id 用于匹配，另存 label 用于界面显示

**实现结构**：

```
anima_webui/combination_rules.py   CombinationRuleStore（JSON 原子写 + AND 匹配）
        ↓ blocked 回调
anima_webui/catalog.py             resolve_prompt 逐维抽样 + 实时校验 + 重抽
        ↓
anima_webui/runner.py              _resolve_catalog_prompt / _fixed_pinned
        ↓ HTTP
anima_webui/server.py              4 个路由
        ↓
static/app.js + index.html         详情弹窗「禁用此组合」+ 规则管理
```

**关键设计决策**：

1. **逐维校验而非抽完再检**。姿势维度有互斥槽位约束（回溯搜索），整体重抽可能永远抽不出可行解。
2. **复用同一个 `rng`**。实测确认：同一种子下无论规则是否触发重抽，两次抽取结果完全一致 —— 这保住了"复现此图"。
3. **重抽耗尽必须报错**，消息点名规则 id，不静默返回被禁组合。

**实测验证**（真实词库 8000 角色）：禁用「初音 + 某服装」后跑 40 个种子，该配对出现 **0 次**。

### 需求 2：生成监视区

**问题根因**（已定位并验证）：

```css
.progress-track div::after { width: 42%; animation: shimmer ...; }
@keyframes shimmer { to { transform: translateX(340%); } }
```

42% × 3.4 = **142.8%**，超出容器。改为 250%（=105%）并加 `isolation: isolate`。

**界面改造**：
- 底栏缩略图 38px → 48px，加展开小三角
- 新增 `#monitorPanel`：预览图 + 四项测量带（批次/当前张/采样/状态）+ 队列
- 触发方式：点击小三角手动展开（用户选定方案）
- 图片区高度 `clamp(140px, 32vh, 260px)`，窗口矮时不顶出屏幕

**避免轮询闪烁的三处处理**：
- 数字只改 `textContent`，不重建节点
- 队列按 signature 比对，只在内容变化时重建
- 预览图按 `preview_id` 去重，同一帧不重复赋值 `src`

**实测**：六种窗口尺寸（1920×1080 至 390×844）全部验证面板不越界、不与底栏重叠，间隙 16–56px。

### 需求 3：ACTUAL DRAW 回填

**问题根因**：
- `catalog.py` 的 `resolve_prompt` 在固定词模式下直接 `continue`，从不写 `selected[section]` → 固定模式的图五维全空
- `runner.py` 的 `_resolve_regeneration` 用历史 `resolved_selection` 作新图的值，为空则新图也空

**修复**：抽 `catalog.fixed_selection_item()` 作唯一事实来源，供三处共用（`resolve_prompt` / `_fixed_pinned` / `_backfill_fixed_sections`）。

**最高优先级安全验证**：用真实模板对比回填前后的 `build_submission` 输出，差异**仅一处**：

```
.extra_pnginfo.anima_random_webui.resolved_selection.background
```

即只有写入 PNG 的历史快照本身变化，**推理参数完全一致** —— 证明回填不影响出图。

## 三、执行过程中的重要修正

改造过程中有 6 个问题是在审查阶段发现并修复的，其中 3 个会直接影响用户：

### 1. 规则在"局部重抽"下静默失效（Critical）

`content_redraw` 路径把未重抽的维度设为 `random_*=False`，这些维度在 `selected` 里恒为空，而规则要求所有维度都命中 → **规则永不生效**。

后果：用户点"禁用此组合"后，对该图做"选择内容重抽"，被禁组合仍会出现。

同时发现原测试**掩盖**了这个问题：测试替身无视 `random_*`，恒定塞入条目。

### 2. 通用标签会导致整个维度被禁（Critical）

第一版固定维度按标签包含匹配。用户若写 `text="1girl"`，几乎所有角色条目都含这个标签 → **整个维度被禁掉**，规则退化成"全禁"。

修复：要求规则必须命中条目的**主身份**（title），通用标签无法蒙中。已直接测四种判据全部正确。

### 3. 底栏网格被新增按钮撑坏（我自己的 bug）

底栏原定义 3 列，我插入 `toggleMonitor` 后变成 4 个子元素挤 3 列 → 布局错位。920px 断点也有同样问题，导致 768px 下与面板重叠 24px。

**这是我在实现 Task 6 时引入的**，上一轮自查没发现，是用户截图指出后才定位。

### 4-6. 其余修正

- 固定维度曾因 `tags[0]` 顺序假设导致规则静默失效（用户把通用标签写在前面时）
- 测试资源泄漏：`HistoryStore` 未 close，Windows 下 `WinError 32`，会让 CI 随机变红
- 空断言：3 条测试永远通过，包括 1 条我要求补但实现者写了两个版本仍无区分力

## 七、使用说明

**重启要求**：Python 改动需重启 WebUI；前端改动刷新页面即可。

**新功能入口**：
- 查看图片 → 详情弹窗 →「禁用此组合」→ 勾选 2-5 个维度 → 确认
- 同弹窗内「管理已有规则」→ 查看 / 删除 / 清空

**已知行为**：
- 规则只对"随机抽取"的维度生效；固定词维度参与匹配，但建规则时该维度会置灰（无 catalog id）
- 老图不会自动补数据，但显示已修好（走 `settings.fixed_*` 回退）
- 规则把候选排除干净时会**明确报错**并点名规则，不会偷偷违反规则出图
